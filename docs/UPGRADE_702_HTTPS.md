# RR 7.0.2 的 Nginx HTTPS 升级兼容

7.0.2 的标准 443 安装使用 Certbot Nginx 插件。7.2.1 的公网域名更新只接受完整的 Webroot 续签配置，因此旧安装会在迁移阶段失败并触发订阅隔离。缺少 Webroot 目录不表示旧证书无效。

本分支补充两项处理：

- 安装器在创建快照和停止服务之前识别旧续签方式，提前拒绝未准备的升级。
- `scripts/migrate-v702-nginx-https.sh` 提供一次性迁移至已发布 7.2.1 的入口。它需要已有升级前备份目录，核对账户与节点身份，严格识别 RR 7.0.2 经 Certbot 修改的站点，只迁移该站点。Certbot `reconfigure` 使用 staging 验证新续签参数；生产证书字节保持不变。

执行方式：`bash scripts/migrate-v702-nginx-https.sh /root/rr-before-7.2.1.XXXXXX`。入口和它下载的验证器、安装器、运行包均使用固定提交或版本及 SHA256。

准备阶段暂时暂停面板和证书定时器，Sing-box 节点继续运行。准备失败会恢复原站点及续签文件。准备成功后保留新续签设置，随后由已发布的事务安装器执行升级并负责回滚、隔离及服务恢复；脚本不会覆盖安装器的回滚决定。升级成功后核对用户身份、服务、订阅隔离解除及健康定时器。

Nginx 原配置、续签原文件及证书/配置校验值保存在 `/root/rr-legacy-https.*`，原有完整备份继续保留。若站点包含未知自定义内容，迁移会在修改前停止。

针对性验证：`tests/test-legacy-https-preflight.sh` 覆盖安装器停止服务前拒绝旧续签配置，以及旧站点识别与外来指令拒绝；`tests/test-legacy-https-rollback.sh` 使用真实临时文件和符号链接验证恢复行为及升级后的职责边界。

此分支中的安装器前置检查尚未进入正式发行版。迁移入口使用现有 7.2.1 发布资产，不要求重新安装或交叉测试三台 VPS。正式服务器上的迁移结果需要实际执行后确认。

如果已经出现 `LEGACY_HTTPS_PREPARED`，但正式升级因防火墙规则被拒绝而回滚，已验证的 HTTPS 准备会保留。不要重复运行旧站点迁移入口。先运行 `scripts/diagnose-v721-firewall.sh`，收集 80/443 的规则归属、IPv4/IPv6、UFW 子检查，以及其他已启用节点端口的检查结果。该诊断不修改防火墙、不启停服务、不执行证书续签，也不输出节点凭据。规则缺失与第三方规则重叠必须按实际结果分别处理，不能用清空规则或跳过校验来继续升级。迁移入口现在也会在暂停服务前检查 80/443。
