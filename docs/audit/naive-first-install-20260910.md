# 7.2.4 候选：Naive 首次安装中断修复

状态：待用户实机验收，尚未发布正式版。

## 已确认的问题

7.2.3 首次安装 Naive 时，准备 HTTP-01 验证会先创建 RR 防火墙保护 drop-in。后续创建 Sing-box 主服务却要求 drop-in 目录为空，因此拒绝自己的文件。现场证书已签发、Sing-box 配置存在、主 unit 不存在而 RR drop-in 存在，与源码顺序一致。不安装 RR Nexus 面板不是该问题的原因。

第二次尝试的防火墙保护服务失败尚没有 journal 证据定位其具体原因；不得把外层“证书申请失败”当作现有证书损坏的证据。

## 本次改动

- 缺少主 unit 时，只接受经现有严格校验确认的 RR 防火墙和恢复 drop-in；未知文件、篡改内容、链接、不安全权限或有效外来服务仍拒绝。
- 服务写入失败提供明确提示；证书准备步骤的失败不再一概声称签发失败。
- 菜单区分脚本安装完成与未完成，避免把已有配置显示成面板已安装。
- 为现场提供固定候选来源的定向恢复工具。工具保持已安装 7.2.3 文件完整，备份后补齐服务并完成节点安装；不会安装 RR Nexus。它不等于升级整套 7.2.4。

## 验证与范围

聚焦回归使用临时目录中的真实文件、权限和链接，systemctl 由 fixture 提供；不能算实机 systemd 或公网协议连接测试。用户回执尚未收到。候选修复函数将在用户故障机的现有状态上执行；这不是空白服务器全新安装、三个系统复测或所有协议端到端验收。

已完成的本地检查：相关 Shell 语法与确定性发布包核验通过；22 项所有权回归通过，其中 foreign-owner 一项因容器不能改变 UID，使用了明确报告的元数据注入。恢复工具的成功退出、前期失败、后期失败三个 EXIT 生命周期 fixture 通过。没有执行恢复工具的真实写操作。

被恢复工具加载的候选模块来自提交 `cfeda272431beaffd03568c7a80c6934927f826a`，`modules/30-singbox.sh` SHA256 为 `dfd6929c22576a49eff09a4c931a958c410225b009f9d96a5679371d8c3ee566`。当前带详细前置检查的恢复工具 SHA256 为 `08cc5994785d79d4b58da2a201c989d65c902ce6d986237748272d4040c4c44e`。终端输出 `CANDIDATE_OWNERSHIP_CHECK_OK` 只证明候选检查在该状态通过，完整恢复还须得到 `REPAIR_COMPLETE` 并由用户确认节点使用正常。

2026-09-10 用户首次执行 `d9a220cd9e6625a81929f9a42584097c4f7e8d03` 中的恢复工具（SHA256 `ef03c674ded75ecdcf68fae819c6e880df007acd4a6c7a8a983077a1e3ebceef`），回报 `REPAIR_STOP phase=writer_lock rc=75`。该回执说明未进入恢复回调，未备份配置或创建服务，不能计入修复成功。75 是 flock 获取失败的映射，通常占锁，但具体占用进程或系统调用错误仍待只读诊断确认。

新增 `scripts/diagnose-rr-writer-lock.py` 按设备号与 inode 读取内核锁和匹配 FD，不读取进程命令参数或环境，不获取/删除锁、不操作服务。使用真实 flock 的本地 fixture 验证匹配及锁文件属性/内容保持；没有连接远程主机。恢复工具现在明确区分日志目录创建与实际配置备份，并直接显示锁获取失败的说明；没有改变或绕过锁机制。

随后用户回报只读诊断：当前新锁文件为 root:root、0600、普通单链接文件，没有匹配的内核锁或打开 FD；legacy 锁和 bridge 均不存在。这说明诊断时已无可见占用，无法追溯先前占用者，也不能据此宣布恢复成功。恢复工具改用原版 `rr_run_with_update_locks isolated 20`，只将新锁从立即尝试改为最多等待 20 秒，保留完整可信性检查，不删除锁或杀进程，不重试已经进入的恢复回调。真实 flock 的本地回归验证了短暂占用后继续、持续占用超时拒绝、回调失败不重复执行；仍待用户重新执行恢复的结果。

用户重新执行 `a136841e78b3f989492bb0e3abe9025114eb414e` 的工具（SHA256 `4646b80d3fd5c62cb65cfa116a08339c7eec39459134fcb9b00ec73e7978ba77`）后已取得写锁，但在 `locked_preflight` 返回 1。仍未进入配置备份或服务写入；具体拒绝项待确认，不据此放宽任何条件。现在把同一前置条件拆为 31 项逐条报告，独立检查全部执行后汇总失败。

新增 `--check` 模式使用同一写锁和同一前置条件，在配置解析、证书操作、配置备份及服务恢复前退出。文件/目录失败输出父链元数据，systemd 只输出白名单属性，不输出 UUID、口令、私钥或服务启动参数。该模式会创建私有日志/校验副本，并通过原版锁 API 核验锁元数据；不是系统零写入探针，但不会修改节点配置或启停服务。

本地聚焦回归使用真实文件和生产权限检查、模拟 systemctl/runtime 验证器：通过现场的 31 项检查全部列出；同时注入配置权限、未知 drop-in、健康 timer 活跃三个拒绝项，确认三个都报告且最终检查仍执行，检查模式不进入配置读取和恢复函数、文件内容和敏感哨兵保持不变。未连接任何远程服务器，尚无恢复成功回执。

旧三台云测试机已由用户删除，不得再次连接。候选仅推独立分支；本提交不改变 main、Latest 或现有正式发布校验。正式发布前须处理退役主机门禁，并如实记录用户执行的候选摘要和结果，不能将未运行的测试记为通过。

## 现场操作边界

恢复工具仅适用于已核对的 Debian 12、7.2.3、无 Nexus、Naive 证书已就绪且 Sing-box 主 unit 缺失的状态。存在隔离/恢复标记、文件不一致、证书或身份前置条件不符时停止并报告阶段；不删除保护标记、不清空防火墙、不重新运行安装向导。

成功后会启动既有节点、临时 Argo、订阅服务和健康检查。端口、UUID、Reality 密钥和 Naive 凭据必须核对不变，首次临时 Argo 域名属于本次新建运行状态。备份、详细日志和敏感身份对照仅保存在服务器 root 私有目录。
