# 7.2.4 候选：Naive 首次安装中断修复

状态：待用户实机验收，尚未发布正式版。

## 已确认的问题

7.2.3 首次安装 Naive 时，准备 HTTP-01 验证会先创建 RR 防火墙保护 drop-in。后续创建 Sing-box 主服务却要求 drop-in 目录为空，因此拒绝自己的文件。现场证书已签发、Sing-box 配置存在、主 unit 不存在而 RR drop-in 存在，与源码顺序一致。不安装 RR Nexus 面板不是该问题的原因。

第二次尝试的防火墙保护服务失败尚没有 journal 证据定位其具体原因；不得把外层“证书申请失败”当作现有证书损坏的证据。

## 本次改动

- 缺少主 unit 时，只接受经现有严格校验确认的 RR 防火墙和恢复 drop-in；未知文件、篡改内容、链接、不安全权限或有效外来服务仍拒绝。
- 服务写入失败提供明确提示；证书准备步骤的失败不再一概声称签发失败。
- 菜单区分脚本安装完成与未完成，避免把已有配置显示成面板已安装。
- 为现场提供固定候选来源的定向恢复工具。工具保持已安装 7.2.3 文件完整，备份后补齐服务并完成节点安装；不会安装 RR Nexus。它不等于升级整套 7.2.4。

## 2026-09-10 隔离标记现场回执与恢复入口

用户在日志目录 `/root/rr-repair-naive723.AOSCjH` 对应的回执中提供了全部 31 项结果：30 项通过，仅防火墙隔离标记不存在这一条件失败。实际标记是 root:root、0600 的普通单链接文件，父目录为 root:root、0700。此时尚未收到标记正文、封存证据或恢复成功的回执；不能据此认定隔离可以直接解除，也不能认定是哪一次进程发布了标记。

新增显式 `--recover-firewall` 模式，使用相同的原版写锁入口。其余 30 项检查保持不变，只把此模式中的“标记不存在”改成名为 `firewall_marker_v2` 的专用检查。默认恢复和 `--check` 仍要求标记不存在。

该模式先获取原版防火墙锁，验证规范的 v2 标记、可用的 v1 证据、原始配置哈希和期望规则集合、完整当前规则快照及保护服务，再把标记、证据、配置、规则和服务日志备份到 root 私有目录。所有被记录的节点及健康检查必须是停止状态、两个 runtime 字段必须为 false，当前加载及启用状态必须与记录一致。然后只调用一次原版 `rr_firewall_repair_fail_closed_quarantine`，由该函数恢复规则与持久化、验证后解除隔离。外层真实防火墙锁一直持有到配置字节和停止状态的后验结束。

独立代码复核补充了 `rr-firewall-quarantine-guard.path` 必须为 enabled 的提前检查：原恢复在变更规则后才会验证这个条件，提前检查可以避免因已知的启用状态不符而在变更后才失败。工具仅查询和报告该条件，不自行 enable。原 guard service 为 failed 本身不需手动 reset-failed；原恢复要求停止后不处于 active。

`firewall-inflight-v1`、证据 unavailable、证据或配置不一致、当前规则漂移等都会在调用原恢复入口之前明确拒绝。工具不伪造 inflight 所有者、不重新封存证据、不直接删除标记，也不把旧配置覆盖回新的隔离证据。专用退出处理只释放本进程实际持有的锁，不进入安装模式的停服或 unit 清理。

隔离模式成功只输出 `FIREWALL_RECOVERY_COMPLETE`，不会创建 Sing-box 主服务、安装面板或启动节点。必须在它成功退出后，另起默认恢复模式完成节点安装；否则不能算本次故障已修复。先解除已验证的隔离再创建主服务，是因为原恢复要求当前 LoadState 与封存时的 not-found 状态一致。

本版恢复工具 SHA256 为 `b763f88705fb43abf9d65ca586b9072fec05a71f157e9f5104a3a745ae429bfd`。调用形式为 `bash /root/rr-repair-naive.sh --recover-firewall && bash /root/rr-repair-naive.sh`；只有前一步成功才继续。它保持安装版本 7.2.3，不能将该回执等同于整套 7.2.4 热更新验证。

聚焦回归 `tests/test-repair-firewall-recovery.sh` 的 18 个场景通过：inflight、不可用证据、错误格式、记录的活动节点/runtime、配置哈希或期望规则不符、证据格式或权限不符、当前加载状态或规则不符、保护服务不符/path 未启用、两种备份失败、原入口返回失败及未释放嵌套锁的失败，以及成功路径。使用真实文件、生产 marker/证据元数据及配置哈希检查、生产可重入 flock；systemd、进程探测、快照布局/当前内核规则和原恢复执行由显式 fixture 代替。没有调用真实防火墙或远程服务。

成功场景验证归档中封存了实际配置、marker 和证据，且备份完成之后才调用一次模拟恢复入口；失败场景验证配置和证据原样保留。真实锁释放在持锁进程尚存活时验证，避免把进程退出自然关闭 FD 当成退出处理正确的证据。原 31 项检查/同时报告三项失败的回归也通过；Shell 语法与 CI YAML 解析通过。用户故障机尚无 `FIREWALL_RECOVERY_COMPLETE` 或 `REPAIR_COMPLETE` 回执。

## 现场操作边界

默认恢复仅适用于已核对的 Debian 12、7.2.3、无 Nexus、Naive 证书已就绪且 Sing-box 主 unit 缺失的状态。存在隔离/恢复标记、文件不一致、证书或身份前置条件不符时停止并报告阶段；不直接删除保护标记、不清空防火墙、不重新运行安装向导。显式隔离恢复模式的额外条件和操作范围见上节。

成功后会启动既有节点、临时 Argo、订阅服务和健康检查。端口、UUID、Reality 密钥和 Naive 凭据必须核对不变，首次临时 Argo 域名属于本次新建运行状态。备份、详细日志和敏感身份对照仅保存在服务器 root 私有目录。
